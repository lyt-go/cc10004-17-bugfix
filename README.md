# 数据产品运营与归因分析平台

面向数据产品运营、渠道归因、用户行为分析、ROI评估、转化优化与数据应用监控的数据分析工程平台。

这是一个**纯前端**管理平台：React + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.tsx`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`；审计域（参数快照、审计异常、修复清单、批次、复核单）种子在
  `frontend/src/data/audit-seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 会话与角色在 `frontend/src/stores/session.ts`：归属负责人可以维护名下内容，越权提交被拒绝，
  只读成员只能查看；鉴权判断集中在 `local-service.ts`。
- 条目与审计域放在同一个存储对象里，所有改动经 `transact` 一次提交落盘：
  事件下线时「规则关闭 + 事件状态 + 异常清理」不会出现写一半的不一致。
- 想回到初始数据：清掉浏览器里 `data-product-ops:store:v2` 这一项，或调用 `resetModule(模块)`。

## 埋点事件与审计规则的生命周期

- 埋点事件：草稿 →（提交事件评审）→ 事件评审中 →（发布事件，建立参数快照与发布凭据）→ 已发布
  →（下线事件）→ 已下线。下线即封存：当前快照封存、关联生效规则同批关闭、未闭环异常与待修复
  清单封存保留，停止新增审计异常。重新发布需重新走评审，发布时**必须建立新的快照**。
- 审计规则：草稿 →（提交规则评审）→ 规则评审中 →（生效规则）→ 已生效 →（关闭规则）→ 已关闭。
  生效前核对审计对象的发布凭据与参数快照都在有效期内，否则拒绝生效。已关闭规则可重新提交评审。
- 审计批次：开批时绑定事件快照版本；提交时若规则已关闭或事件版本已切换，只采纳**首个完整
  审计批次**作为终批（产出直接封存），后到批次进入复核队列，由归属负责人裁决采纳或驳回。
- 修复清单版本口径：每条修复清单**按生成时的参数快照版本解释**，封存后不再改写；重新发布事件后，
  新产出的清单按新快照的参数生成，历史清单不沿用、也不回填新参数。
- 事件质量结论由 `eventQuality()` 统一计算，事件详情页与审计详情页展示同一份，保证两处口径一致。
